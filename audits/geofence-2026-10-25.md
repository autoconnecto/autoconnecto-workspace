# Geofence corrections — 25 Oct 2026

Status: local only. Not deployed. Not board-verified.

Code review + static only — not board-verified. The lockout example was not sent to a device.

## What changed

1. Latitude outside -90 to 90 and longitude outside -180 to 180 go to failure. The remembered inside/outside state is not written.
2. Degrees × 1e6 go to failure with that reason. They are not a supported unit.
3. A latitude that only fits as a longitude is named in the failure note. Reject swapped data is an optional node switch, default off. It fails an India-shaped swap. A real site with the same shape fails too.
4. Preview asks the saved fence and shows inside or outside. It does not remember the previous point, so entered and left are not shown.
5. Accepted forms are documented: numeric keys, numeric strings, and a location or gps object.
6. Customer page: Geofences. Fence record, five outputs, first-sample rule, permanent enter/exit alarms, profile binding, Preview.
7. Geofences screen: map, circle or polygon, name, enter and exit alarms. The switches start off. PATCH updates a fence.
8. The editor warns when entered or left is not connected. Treat a crossing as inside or outside sends the crossing on those branches and keeps geofence_crossing.
9. A run that takes a failure output increments the engine failure count.
10. Polygon and several-fence geometry are covered by unit tests. Enter and exit alarm decisions are covered by unit tests. Example: Block the next start links outside and left to a blockNextStart command with once true, and failure to a log. The command test uses a mock. It does not send hardware.
