## New problems and observations

| ID | Severity | Description |
|---|---|---|
| NEW-5 | Minor (likely local-environment) | On local, `GET /api/dashboards/<id>` and `GET /api/devices/<id>` return `createdAt` about 5 h 30 min earlier than the real time. Example: a dashboard created at about 02:16 UTC (07:46 IST) reads `2026-10-25T20:46:34Z`. The `POST` response for the same kind of object gives the right time (`2026-10-26T02:26:50Z`, matching the PC clock and the backend /health Date header). So the dashboards list shows "26 Oct 2026, 02:16 am IST" for something created at 07:46 IST, and the device Created date is early too. Telemetry/purchase times, OTA, audit and rule-engine versions are correct. The pattern looks like a timestamp without a zone being read as server-local time, probably because the API process runs with an IST clock, and it may not show on a UTC server. It was already present in round 1 (a dashboard created at about 05:56 IST showed 12:26 am). It limits the NEW-3 check. |
| Obs-1 | Cosmetic | A fuel purchase (`POST /api/fuel/purchases`) is audited as entity "OTHER" with a blank name. |
| Obs-2 | Cosmetic | OTA Assign "Target" dropdown labels show the raw id in brackets: "QA-A178L-R2 Dev2 (device-063e3d8a-…)". |
| Obs-3 | Minor | If the page is left while the widget config modal is open (not Cancel), the unconfigured placeholder (`_pendingConfigure`) stays saved on the dashboard as a blank "Widget not configured" tile. |
